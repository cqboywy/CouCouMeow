# 凑凑喵英语乐园阶段 0 工程基础设计

## 1. 目标与范围

本设计定义凑凑喵英语乐园的阶段 0 工程基础。阶段 0 交付可启动、可测试、可部署的前后端骨架、Supabase 数据基础和本地内容入库工具，但不实现完整学习业务页面。

完整分阶段任务与验收标准见 `docs/project-roadmap.md`。阶段 0 完成后，阶段 1–3 仍需分别完成设计、实施和验收。

## 2. 已确认的技术栈

- 项目组织：pnpm monorepo。
- 前端：React、Vite、TypeScript。
- 后端：Python 3.12、FastAPI、Pydantic、uv。
- 数据库与认证：Supabase PostgreSQL、Supabase Auth、Row Level Security。
- 本地入库工具：Python，复用后端的数据模型和验证规则。
- 接口契约：FastAPI OpenAPI 生成 TypeScript API 客户端。
- 前端测试：Vitest、Testing Library、Playwright。
- 后端与工具测试：pytest。
- 持续集成：GitHub Actions。
- 目标部署：Vercel 前端、Railway 或 Render 后端、Supabase 托管数据库；同时保留容器部署能力。

## 4. 系统边界

网站是标准响应式 Web 应用，不限制设备类型。iPad 是主要设计与触控验证基准；手机浏览器提供适合窄屏的单列布局，电脑浏览器提供合理的内容宽度和键盘操作支持。三类设备均支持完整学习流程，不把手机或电脑降级为只读模式。

### 4.1 当前媒体策略

阶段 0 和阶段 1 初始版本不上传或在线播放 MP4。数据库保存本地视频文件名，前端显示本地观看提示。数据结构预留媒体提供方与媒体定位字段，未来可以增加浏览器本地文件播放或 Supabase Storage，而不重做核心内容模型。

本地 MP4 和 SRT 路径只存在于入库工具的本地配置或命令参数中，不提交 Git。`.gitignore` 必须排除媒体文件、字幕文件、环境变量和视觉设计临时目录。

### 4.2 身份策略

使用家长邮箱登录，一个账号对应一个孩子档案。Supabase Auth 用户 ID 是个人学习数据的权限主体。设计保留未来增加多个档案的可能，但阶段 0 不实现多孩子切换。

### 4.3 服务边界

- 前端负责儿童交互、录音采集和学习内容展示。
- FastAPI 负责判题、练习记录、错题聚合、统计和外部服务适配。
- Supabase 负责持久化、认证和数据权限。
- 本地入库工具负责读取本地素材、调用内容生成服务、验证并写入内容库。
- 外部 AI 与语音服务通过接口适配，不将供应商逻辑散落到业务代码。

## 5. 数据设计

### 5.1 内容表

#### `lf_episodes`

- `id`: UUID 主键。
- `level`: 1–9 的小整数。
- `title`: 剧集标题。
- `local_video_filename`: 本地视频文件名，不保存绝对路径。
- `local_srt_filename`: 本地字幕文件名，不保存绝对路径。
- `is_learned`: 当前家庭中唯一孩子的已学标记。项目扩展为多孩子前必须迁移到独立进度表。
- `content_status`: `draft`、`validated` 或 `published`。
- `content_hash`: 清洗后字幕的稳定哈希。
- `media_provider`: 当前为 `local`，为未来媒体能力预留。
- `media_locator`: 当前为空；未来只存服务端可解释的定位信息。
- `created_at`、`updated_at`: 带时区时间戳。

同一 Level 下 `local_video_filename` 唯一。网站只读取 `published` 剧集。

#### `lf_sentences`

- `id`: UUID 主键。
- `episode_id`: 关联 `lf_episodes`，删除剧集时级联删除。
- `sequence_no`: 原句顺序。
- `english_text`: 清洗后的英文原句。
- `chinese_translation`: 中文翻译。
- `created_at`: 带时区时间戳。

同一剧集中 `sequence_no` 唯一。

#### `lf_vocab`

- `id`: UUID 主键。
- `episode_id`: 关联 `lf_episodes`。
- `word`: 英文单词。
- `phonetic`: 音标。
- `chinese_meaning`: 中文释义。
- `sequence_no`: 展示顺序。
- `created_at`: 带时区时间戳。

同一剧集内对规范化后的单词建立唯一约束。

#### `lf_knowledge`

- `id`: UUID 主键。
- `episode_id`: 关联 `lf_episodes`。
- `title`: 知识点短标题。
- `grammar_explanation`: 适合小学阶段的句型语法讲解。
- `core_knowledge`: 本集核心知识点。
- `sequence_no`: 展示顺序。
- `created_at`: 带时区时间戳。

### 5.2 学习表

#### `profiles`

关联 Supabase Auth 用户，保存孩子显示名、时区和创建时间。RLS 只允许用户访问自己的档案。

#### `practice_sessions`

保存一次练习的用户、剧集、练习类型、开始时间、完成时间、题目数、正确数和得分。练习类型覆盖中文听写、音频听写、句子跟读和复习。

#### `practice_attempts`

保存每题对应的词汇或句子、标准答案、用户答案、语音转写、相似度、原始判定、人工修正判定、修正原因和创建时间。词汇引用和句子引用必须二选一。

#### `mistake_items`

按用户和内容项唯一聚合错词或错句，保存错误次数、最近错误时间、掌握状态、复习阶段和下次复习时间。阶段 2 直接基于该表实现 1、3、7 天调度，练习历史继续保留在 `practice_attempts` 中。

### 5.3 系统表

#### `content_import_jobs`

记录单集或批量任务的运行 ID、模式、输入文件名、字幕哈希、状态、错误代码、错误摘要和时间。它用于断点续跑与审计，不保存字幕全文、密钥或绝对本地路径。

### 5.4 数据权限

- 内容表：登录用户可读取已发布内容；服务端角色负责内容写入。唯一例外是登录用户可以通过受限后端接口更新 `lf_episodes.is_learned`，不能修改其他内容字段。
- 学习表：只允许当前 Auth 用户读写自己的记录。
- 系统表：只允许服务端角色访问。
- 所有策略必须有数据库级自动测试。
- 前端只使用 Supabase 公共匿名密钥，不持有服务端角色密钥。

## 6. 内容入库流水线

入库命令支持三种用法：单集处理、指定目录批量处理和任一模式的 `--dry-run`。

```text
发现并配对 MP4/SRT
→ 解析 SRT
→ 清洗与合并英文句子
→ 生成字幕哈希并查重
→ 调用 ContentGenerator 接口
→ 使用 Pydantic 验证结构化结果
→ 事务写入 draft 内容
→ 生成人工校验摘要
→ 人工确认 validated/published
```

批量模式必须满足：

- 单集失败不阻断其他剧集。
- 已存在且哈希未变化的剧集自动跳过。
- 字幕变化时将新结构化结果保存为本地待复核 JSON，并在 `content_import_jobs` 中记录待处理状态，不覆盖已发布内容。只有显式执行带确认参数的替换发布命令时，才通过事务替换该集内容。
- 默认写入 `draft`，批量成功不等于网站立即显示。
- 支持安全重试和断点续跑。
- 模型名称通过 `DEEPSEEK_MODEL` 配置，不硬编码易变名称。

`ContentGenerator` 接口接收剧集元数据和清洗后的句子，返回双语句子、重点词汇和核心知识点。测试使用确定性替身，不调用真实 API。

## 7. 语音与判题边界

阶段 0 定义 `SpeechTranscriber` 接口：输入音频，输出转写文本、置信度和供应商元数据。本阶段只实现测试替身，不绑定具体供应商。

阶段 1 的音频默认只用于即时转写，处理完成后删除，不长期保存。人工修正保留原始转写、修正结果和修正原因，以便区分孩子读错与识别误差。

判题逻辑与供应商解耦：

- 单词先做大小写、首尾空格和可配置标点规范化，再进行精确拼写比较。
- 句子先规范化，再计算可解释的文本相似度。
- 自动判定和人工修正同时保留，不覆盖原始结果。
- 任何错误判定都通过统一服务写入 `mistake_items`，不依赖前端手工录入。

## 8. UI 设计系统

### 8.1 方向

正式方向为“凑凑喵的绘本乐园”：可爱但不低幼，像一本可互动的猫咪英语绘本。凑凑喵是奶油白小猫，具有蜜桃色耳朵和淡紫围巾，性格温柔、好奇，陪孩子一起尝试和进步。

图片化设计探索因当前环境的内置图片生成服务不可用而暂停。阶段 0 只建立可编码的设计令牌与组件边界，不使用低质量占位插画。首版优先采用风格一致的开源图标库；原创角色插画在可生成或获得正式素材后加入。

### 8.2 色彩与排版

- 大面积背景：奶白 `#FFF9F2`。
- 主要强调：蜜桃粉 `#F5B8B2`。
- 次要强调：奶蓝 `#CFE7F5`、淡紫 `#DDD4F4`。
- 正文：深葡萄灰 `#514659`。
- 正确反馈：低饱和薄荷绿。
- 错误反馈：柔和杏色，不使用高刺激纯红。

中文以清晰易读为第一优先，英文采用圆润字体。正文不小于 16px，英文练习内容使用 20–28px。全站最多使用两个字体家族。

### 8.3 组件与触控

- 卡片圆角 20–24px，按钮圆角 16–20px，阴影轻薄。
- 主要按钮高度不低于 52px，练习主按钮目标高度 60px；该触控标准同时适用于 iPad 和手机。
- 所有可点击区域至少 48×48px。
- 每屏只有一个最重要的学习动作，避免仪表盘式卡片堆叠。
- 首页突出“今天继续学习”，Level 列表保持安静并可折叠。
- 已完成状态使用小爪印语义，不使用刺激性的排行榜。
- 正式功能图标不使用 Emoji；选择支持猫、爪印、鱼、声音和录音语义的统一开源图标库。

### 8.4 反馈与动效

- 答对文案：“太棒啦，这个单词被你抓住了！”
- 答错文案：“差一点点，凑凑喵陪你再听一次。”
- 连续答错时提供“听一遍”“看提示”“稍后再练”。
- 动画时长控制在 150–350ms，只使用眨眼、摆尾、爪印轻弹等局部反馈。
- 尊重系统减少动画设置，不使用持续飘动、闪烁和大面积粒子。

## 9. 错误处理与可观测性

后端使用统一错误结构，包含稳定错误代码、追踪 ID 和可安全展示的消息。儿童界面将技术错误转换为温柔且可操作的提示；详细原因只进入结构化服务端日志。

日志禁止输出密钥、完整音频、敏感个人数据和本地绝对路径。入库批次记录成功、跳过、待复核与失败状态。单集内容写入使用数据库事务，避免产生半集数据。

## 10. 测试策略

- 前端单元与组件测试：Vitest、Testing Library。
- 后端和入库工具：pytest。
- 核心浏览器流程：Playwright。
- 数据库：约束、级联、事务函数和 RLS 测试。
- 入库工具：固定的虚构 SRT 样本覆盖清洗、配对、查重、失败隔离和 `--dry-run`。
- API 契约：验证 OpenAPI 客户端可重复生成且类型检查通过。
- 响应式：以 iPad 竖屏和横屏为优先设计基准，同时验证手机窄屏和电脑宽屏的完整功能、键盘操作与内容可读性。
- 无障碍：触控面积、键盘焦点、颜色对比度和减少动画设置。

## 11. 部署与配置

前端目标为 Vercel，后端目标为 Railway 或 Render，数据库与认证使用 Supabase。仓库同时提供容器配置，使后端可以迁移到任意支持容器的平台。

`.env.example` 只列出变量名和说明。前端变量和服务端变量分组管理，服务端角色密钥与 DeepSeek 密钥只出现在后端或本地入库工具运行环境中。

## 12. 阶段 0 完成标准

- 前端、后端和入库工具具有清晰、独立的启动命令。
- 前端可以调用后端健康检查。
- 空 Supabase 项目可以完整执行迁移。
- RLS 测试验证个人数据隔离。
- `single` 和 `batch --dry-run` 可以解析虚构字幕样本。
- 无真实外部服务密钥时全部单元测试可运行。
- CI 完成格式、类型、测试和构建检查。
- README 提供中文安装、启动和验证步骤。
- 仓库不包含本地真实素材、密钥或绝对路径。
